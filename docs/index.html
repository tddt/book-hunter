WHAT IT DOES

把「管书」和「读书」放进同一处

不追求功能清单最长，只解决一件事：硬盘里明明有几百本书，却总没有一个愿意在里面把书读完的地方。

01 / 五种格式，一套体验

导入即归一

非 EPUB 格式在导入时转成标准 EPUB 并回喂解析器做结构自校验，绝不写出「能写不能读」的文件。单文件、多文件、整文件夹递归、拖拽、双击 .epub 自动导入，SHA1 去重。

NormalizedBook → buildEpub()
02 / 自研排版引擎

版心由自己算

不依赖 epub.js。CSS 多列分页几何让版心居中、宽屏双页不裁字，跨章翻页自动归零重排；真实页码与按字数加权的全书进度分开计算，翻页有方向一致的动画。

NativeReaderEngine
03 / 真·全文检索

跳到那一页

书名、作者、出版社、分类、标签走倒排索引（毫秒级）；整本正文走可中断的流式扫描。命中片段点一下，直接落到它所在的那一页并高亮。

MiniSearch + 流式扫描
04 / 沉浸式阅读

界面懂得让开

工具栏默认隐藏，鼠标移到边缘才浮现。5 套纸张主题，字号、行距、段距、版心宽度可调；目录、书签、5 色划线、笔记、书内搜索、全屏与快捷键，关闭重开回到上次位置。

浅色 / 深色 / 跟随系统
05 / 正文内对照翻译

译文跟着原文翻页

译文按段落注入正文，与原文共用版心、字号、行距和翻页，而不是挤在侧边小字抽屉里。三态切换、15 种目标语言、第二对照语言、划词翻译，译文落盘后离线可读。

原文 + 译文 / 仅译文 / 仅原文
06 / 整理与找书

书库是自己的

分类树、多标签、收藏、阅读状态、评分、网格 / 列表视图；聚合 Gutenberg、Gutendex、Standard Ebooks、Open Library、Internet Archive 五个公版书源，支持自定义 OPDS 与 EPUB 直链。

全部数据在 %APPDATA%\书猎\library\
THE READING ENGINE

为什么连排版引擎都自己写

中文版心、宽屏双页不裁字、以及一个能让人相信的「读到全书 43%」，都要求对分页几何有完全的控制。于是没有用现成方案：EPUB 解压、章节 HTML 清洗、CSS 多列分页、跨章方向处理、页码与进度映射，全部自己算。

代价是所有排版边界都要自己维护（README 里如实列了退化场景），换来的是五种格式在同一个版心里读起来一模一样。

HONEST LIMITS

也有不做的

把边界写清楚，比多写三条卖点更重要。下面这些是当前版本确实做不到、或不打算做的事。

×
不加载 EPUB 原书样式表 —— 为保证版心统一，特殊诗歌 / 表格排版会退化为通用排版。
×
PDF 不保留原版式 —— 只抽文本层，扫描版需先 OCR；追求原版式请直接用 PDF 阅读器。
×
不支持 DRM 与 KFX —— MOBI 仅处理 MOBI6 / KF8，不绕过任何鉴权或付费墙。
×
只收公版书 —— 在线书源限定公有领域或明确免费授权的内容，不接盗版源。
×
不是手机 App —— 「手机布局」指窗口 ≤640px 的响应式界面，不含移动端打包与触摸翻页。
×
翻译通道有额度限制 —— 用免费公开接口，遵守服务方条款；可换自建 LibreTranslate 端点。
GET STARTED

两种开始方式

直接下载预编译安装包，或从源码自己构建。环境要求 Node.js 20+、pnpm 9+。

完整取舍与目录树见仓库 docs/DEVELOPMENT.md
所有书目、进度、书签、笔记与译文缓存都在 %APPDATA%\书猎\library\。备份这一个目录即可完整迁移；删除书籍默认只移除书库记录，不动原文件。

FAQ

可能被问到的

书和笔记会被上传吗？

不会。应用不需要账号，书目、进度、书签、笔记和译文缓存全部保存在本地 %APPDATA%\书猎\library\，网络只用于你主动发起的在线取书和翻译请求。备份这一个目录即可完整迁移。

支持哪些格式？PDF 效果如何？

EPUB 原生入库；MOBI / AZW3 / PDF / TXT 导入时统一转成标准 EPUB，因此共用同一套目录、进度、检索与标注。PDF 只抽取文本层，保留文字与图片但不保留原版式，扫描版需要先做 OCR。MOBI 支持 MOBI6 / KF8，不支持 DRM 与 KFX。

「在线取书」的书从哪来？有盗版吗？

聚合 Project Gutenberg、Gutendex、Standard Ebooks、Open Library、Internet Archive 五个公版书源，也支持自定义 OPDS 目录和 EPUB 直链。只收录公有领域或明确免费授权的内容，不接盗版源、不绕过登录或付费墙。内置书源以英文公版书为主。

有手机版吗？

目前没有。窗口收窄到 ≤640px 时界面会自动切换成底部标签栏的响应式布局，但项目不含 Android / iOS 打包，也没有触摸翻页手势。

对照翻译稳定吗？断网还能看吗？

仅使用面向公众免费开放、无需 API Key 的接口，有额度与频率限制，可用自建 LibreTranslate 端点替代。译文会落盘缓存，缓存过后离线可读；译文质量与可用性由各服务方决定。

为什么不用 epub.js？

中文版心、宽屏双页不裁字、真实页码与按字数加权的全书进度，需要对分页几何有完全控制，所以自己写了基于 CSS 多列的渲染引擎。代价是所有排版边界都要自己维护，已知退化场景在 README「已知边界」里列明了。

怎么参与？

项目以 MIT 开源，欢迎 Issue 与 PR。提交前至少跑一次 pnpm typecheck，并在描述里写清「改动前的行为 / 改动后的行为 / 怎么验证」。最缺的是排版与分页边界的回归测试、非 Windows 打包适配，以及 EPUB 样式兼容策略。
